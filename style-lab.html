① 候选菜单（trigger popup）

菜单本体是宿主渲染的，插件只贡献：分组源名（中文硬编码）、候选列表、排序/消歧、错误候选，以及桌面端布局覆盖。 以下每个卡片都是一个真实的局部渲染样例；明/暗、≥768px 布局拉伸由全局主题与窗口宽度决定（窄屏演示见「断点」节）。

② 草稿 chips（隐形引用）

文件引用=蓝色、会话引用=紫色；透明底、无圆角、无药丸——只有颜色区分。 标签是「绝对定位」画在宿主 chip 占位块里的，占位块宽度 = textarea 里 U+FFFC 的 advance，过长标签会被裁剪（上游限制，如实呈现）。 开启「显示原始草稿文本」可看到 textarea 里每个引用其实只有一个 U+FFFC 占位符。

③ 发送前探活：失效引用阻塞发送

发送时 codec.serialize 先探活（resolve-session / stat-file）。失效 → serialize 抛错 → 发送被阻塞、草稿保留、错误可见（不是静默降级）。

④ 发送后转录（snapshot 模式）

用户消息显示剥掉 URI 的可读文本；类型与来源由上下文行承载。文件引用序列化为绝对路径（无 @ 前缀），会话引用序列化为 @[标题](dsh-session:…) 。 快照列在用户消息之前（untrusted 前缀）。

⑤ 溢出与降级（转录可见，绝不静默）

超过 3 条、自身引用、重复引用、快照加载失败、单消息处理失败——全部给出一条转录可见的 notice 行，模型与用户都能看到。

⑥ reference（lazy）模式 · read_session

只注入会话身份 + 读取指引（form: notice），模型按需调 read_session，返回分页内容（双重上限，truncated + next_cursor 续读）。工具卡片为 host generic。

⑦ 桌面 / 窄屏断点对比

插件的布局覆盖只在 @media (min-width: 768px) 生效。下面用 iframe 模拟不同设备宽度（媒体查询按 iframe 自身宽度响应）：桌面 = 菜单拉满 composer 卡片宽度、主标签弹性铺开、副标签截断 34%；窄屏 = 回退宿主默认布局。

iframe 内的 CLIENT_STYLES 与宿主背景 CSS 由上方两个 style 标签动态注入，保证和主画廊同一份规则。
